# CH01 — RCC/PLL 100MHz 클럭 설정 및 오실로스코프 실측 검증

> **한 줄 요약:** HAL 없이 레지스터 조작만으로 SYSCLK 100MHz를 구성하고,
> MCO2 출력을 오실로스코프로 실측하여 **이론값 대비 오차 +1.3%** 로 검증했다.
> 이 과정에서 3건의 계측 오류를 순차적으로 진단·해결하며 측정 신뢰성을 확보했다.

---

## 1. 목표

- HSI 16MHz → PLL → **SYSCLK 100MHz** 구성 (STM32F411 최대 동작 주파수)
- 설정된 클럭이 "코드상으로만 100MHz"가 아니라 **물리적으로 실재하는지** MCO2(PC9) 핀 출력을 통해 계측기로 증명
- 클럭 설정 시퀀스의 순서 의존성(VOS → Flash latency → PLL → 버스 분주 → SW 전환)을 이해하고 구현

## 2. 구현

### 2.1 PLL 파라미터 설계

| 파라미터 | 값 | 근거 |
|---|---|---|
| PLLM | 8 | VCO 입력 = 16MHz / 8 = **2MHz** (RM0383 권장 1~2MHz 상한) |
| PLLN | 100 | VCO 출력 = 2MHz × 100 = **200MHz** (허용범위 100~432MHz) |
| PLLP | /2 | SYSCLK = 200MHz / 2 = **100MHz** |
| AHB | /1 | HCLK = 100MHz |
| APB1 | **/2** | F411 APB1 최대 50MHz 제약 준수 |
| APB2 | /1 | 100MHz |

### 2.2 순서가 강제되는 설정 시퀀스

```c
/* 1) PWR 클럭 인에이블 + VOS Scale 1 — 100MHz 동작의 전제조건 */
RCC->APB1ENR |= RCC_APB1ENR_PWREN;
(void)RCC->APB1ENR;                     /* 에라타 대응 더미 리드 */
PWR->CR |= PWR_CR_VOS;

/* 2) Flash 3WS — PLL 전환 "전에" 반드시. 순서 위반 시 하드폴트 */
FLASH->ACR = FLASH_ACR_LATENCY_3WS
           | FLASH_ACR_PRFTEN | FLASH_ACR_ICEN | FLASH_ACR_DCEN;
while ((FLASH->ACR & FLASH_ACR_LATENCY) != FLASH_ACR_LATENCY_3WS) { }

/* 3~7) HSI 확인 → PLL 설정/기동 → 버스 분주 → SW=PLL 전환 (main.c 참조) */
```

**설계 노트**
- `RCC->AHB1ENR` 인에이블 직후의 더미 리드는 STM32F4 에라타
  *"Delay after an RCC peripheral clock enabling"* 대응이다. AHB 버스 지연으로
  인에이블 직후 페리페럴 레지스터 쓰기가 무시될 수 있다.
  **HAL이 내부적으로 처리해주는 것을 레지스터 레벨에서는 직접 책임져야 하는 대표 사례.**
- `GPIOA->MODER`는 리셋값이 `0xA8000000`으로 PA13/PA14(SWD)가 AF 설정되어
  있으므로, 전체 쓰기가 아닌 read-modify-write로만 조작했다.
  (전체 쓰기 시 디버거 연결이 끊긴다.)

### 2.3 검증 경로 — MCO2

PC9를 AF0(MCO2)으로 설정, SYSCLK/5를 출력:
- 이론 출력 = 100MHz / 5 = **20MHz** (주기 50ns)
- 프리스케일러를 /5로 둔 이유: 100MHz 원신호는 프로브/스코프 대역폭 한계에서
  파형 무결성을 확보하기 어려우므로, 검증 가능한 주파수 대역으로 낮춰 출력

## 4. 계측 문제 해결 기록 — 3건

측정 초기에 **물리적으로 불가능한 값들**(74MHz, 34MHz, Pk-Pk 7.6V, 최저점 -2.24V)이
관측되었다. F411의 최대 클럭이 100MHz이므로 74MHz×5=370MHz는 존재할 수 없는
신호라는 판단에서 출발하여, 원인을 순차적으로 분리·제거했다.

| # | 증상 | 원인 | 해결 | 판별 근거 |
|---|---|---|---|---|
| 1 | 20MHz 사각파가 사인파처럼 뭉개짐 | 스코프 **대역제한 필터(20MHz)** 활성 상태 | 필터 OFF | 측정 대상 주파수와 필터 차단 주파수가 일치 → 고조파 소실 |
| 2 | 진폭이 측정마다 요동 (1V~7.6V) | 프로브 팁 ↔ 핀헤더 **접촉 불량** | M-F 점퍼로 기계적 고정 | DMM 평균전압은 안정(1.3V) ↔ 스코프 순간값만 요동 → 접촉 경로 문제로 특정 |
| 3 | 최저점 **-2.24V** 등 물리적 불가능 값 | **그라운드 리드 인덕턴스** (긴 악어클립) | 프로브 슬리브 제거 후 단축 점퍼로 그라운드 직결 | GPIO는 0~3.3V만 출력 가능 → 음전압은 계측 아티팩트로 확정. 조치 후 첨두치가 3.6~3.8V 범위로 안정화 |

**교훈:** 주파수/주기 측정은 제로크로싱 타이밍 기반이라 위 오류들의 영향을 적게 받아
일관된 값(20.2~20.4MHz)을 유지한 반면, 순간 전압 측정은 그라운드 경로와 접촉 품질에
직접적으로 좌우되었다. **계측기가 표시하는 숫자를 그대로 믿지 않고, 물리적 타당성으로
교차검증하는 습관**이 이 챕터의 실질적 산출물이다.

## 5. 한계

- 사용 장비(TDS224, 100MHz 대역폭·1GS/s)에서 20MHz 신호의 파형 미세 형상(모서리
  샤프니스)은 실시간 샘플링 한계로 완전한 재현이 어렵다. 본 챕터의 결론은 파형
  형상이 아닌 **주파수 정량 측정**에 근거한다.
- HSI 기반이므로 ±1~2% 수준의 주파수 오차는 원리적으로 제거 불가.
  정밀 클럭이 필요한 응용(USB 등)은 HSE가 전제되어야 함을 확인했다.

  # CH02 — GPIO 드라이버 설계, OSPEEDR 슬루레이트 실측, 함수 추상화 비용 정량화

> **한 줄 요약:** 레지스터 레벨 GPIO 드라이버를 직접 설계하고 두 가지 실험을 수행했다.
> ① OSPEEDR 4단계 실측 — **무부하 조건에서는 설정 간 차이가 발현되지 않음**을 확인하고
> 부하 의존성으로 원인을 규명했다. ② 함수 추상화 비용 벤치마크 — 별도 컴파일 단위의
> 함수는 -O2에서도 **4.8배** 느렸으나, `static inline` 전환으로 **레지스터 직접 접근과
> 완전히 동일한 성능(5 cycles/toggle)** 을 달성했다.

---

## 1. 목표

1. 재사용 가능한 GPIO 드라이버(`my_gpio.h/.c`)를 레지스터 레벨로 설계
2. OSPEEDR(슬루레이트) 4단계가 상승시간/오버슈트에 미치는 영향 실측
3. "함수로 감싸면 느려진다"는 통념을 **DWT 사이클 카운터로 정량화**하고,
   극복 방법(`static inline`)까지 실증

## 2. 실험 A — OSPEEDR 슬루레이트 실측

### 2.1 방법

- 대상: PC8 (외부 회로가 전혀 연결되지 않은 자유 핀 — LD2처럼 LED/저항이
  달린 핀은 파형 왜곡으로 배제)
- BSRR 토글 루프로 구형파 생성, OSPEEDR을 00→11로 변경하며 4회 반복 측정
- 상승시간: 사용 장비(TDS224)에 자동 Rise Time 측정 기능이 없어
  (TDS2MM 확장모듈 필요) **Voltage 커서로 10%/90% 레벨(0.36V/3.16V)을 산출한 뒤
  Time 커서로 ΔT를 수동 측정**하는 표준 절차를 수행

### 2.2 결과

| OSPEEDR | 첨두치 | 상승시간 (10–90%) |
|---|---|---|
| 00 (Low) | 3.52V | **82ns** |
| 01 (Medium) | 3.52V | ~80ns (오차범위 내 동일) |
| 10 (Fast) | 3.52V | 동일 |
| 11 (High) | 3.52V | 동일 |

### 2.3 분석 — 왜 차이가 없는가

4단계 모두 동일 값으로 수렴한 것은 오측정이 아니라 **부하 조건의 귀결**이다.

- 슬루레이트 제어의 본질은 출력 드라이버의 구동 능력(등가 임피던스 R) 조절이며,
  상승시간은 **τ ≈ R × C_load** 에 지배된다.
- 본 실험의 부하는 프로브 입력 커패시턴스(10x 프로브, 십수 pF)뿐으로,
  데이터시트 슬루레이트 스펙의 표준 시험 조건(≈50pF)보다 훨씬 가볍다.
- **C_load가 충분히 작으면 R의 차이가 τ에 유의미하게 반영되지 않는다** —
  4단계가 82ns 부근으로 수렴한 것은 이 조건에서 이론적으로 예측되는 결과다.

**실무적 시사점:** 슬루레이트 설정의 효과는 부하 의존적이다. 버튼·LED처럼
가벼운 부하의 GPIO에 High 설정을 쓰는 것은 속도 이득 없이 EMI 방사 리스크만
키우는 선택이며, **"요구 속도를 만족하는 최저 슬루레이트"가 올바른 기본값**이다.
가전제품은 EMI 인증이 출하의 실제 관문이므로 이 원칙의 무게가 크다.

## 3. 실험 B — 함수 추상화 비용 정량화

### 3.1 방법

- DWT 사이클 카운터(`CYCCNT`)로 10,000회 토글 소요 사이클 측정

- 컴파일러의 루프 제거를 막기 위해 결과 변수를 `volatile`로 선언

### 3.3 분석

- **-O2에서도 4.8배 차이가 남는 이유:** GCC는 링크 타임 최적화(LTO) 없이는
  **다른 컴파일 단위(translation unit)의 함수를 인라인하지 않는다.**
  `my_gpio.c`에 구현된 함수는 호출(call/return) 오버헤드가 그대로 잔존했다.
- **`static inline` 전환 효과:** 함수 본문을 헤더로 이동해 호출부와 같은
  컴파일 단위에 두자, -O2에서 **레지스터 직접 접근과 1 cycle 이내로 동일**해졌다.
- 이는 CMSIS를 포함한 임베디드 라이브러리들이 저수준 접근자를 헤더에
  inline으로 구현하는 설계 관행의 근거를 직접 재현한 것이다.

**결론:** "추상화 = 성능 손실"은 조건부 명제다. 컴파일 단위 배치를 이해하고
`static inline`을 적용하면, **가독성·재사용성·타입 안전성을 가진 드라이버
계층을 제로 코스트로 구축할 수 있다.**

## 4. 산출물

- `my_gpio.h` — `static inline` 접근자 + 초기화 API (재사용 가능, 이후 챕터의 기반)
- `dwt.h` — 사이클 정밀 벤치마크 유틸리티 (10ns 분해능 @100MHz)

## 5. 한계 및 후속 계획

- 슬루레이트 실험은 무부하 단일 조건이므로, 표준 부하(수십 pF) 조건에서의
  단계별 차이 분화는 검증하지 못했다. 부하 커패시터를 추가한 조건별 재실험은
  후속 과제로 남긴다.
- HAL(`HAL_GPIO_TogglePin`) 동일 조건 비교는 HAL 미포함 프로젝트 구성상
  제외했다. 별도 브랜치에서의 비교를 후속 과제로 남긴다.

# CH04 — EXTI 인터럽트, 버튼 바운스 실측, 소프트웨어 디바운싱

> **한 줄 요약:** 레지스터 레벨로 EXTI 외부 인터럽트를 구현하고, 온보드 버튼(B1)과
> 외부 택트스위치의 기계적 바운스를 오실로스코프 싱글샷으로 실측했다. 두 스위치 모두
> 예상보다 미미한 바운스를 보였으며, 100회 반복 실험으로 디바운싱 유무에 따른 검출
> 차이를 정량 비교했다. **"측정해보니 문제없었다"와 "디바운싱을 생략해도 된다"는
> 다른 명제**라는 안전 마진 관점의 결론을 도출했다.

---

## 1. 목표

1. EXTI 외부 인터럽트를 레지스터 레벨로 구현 (SYSCFG → EXTI → NVIC 경로)
2. 버튼의 기계적 채터링(bounce)을 오실로스코프 싱글샷으로 직접 캡처
3. 온보드 B1(PC13)과 외부 택트스위치(PB0)의 바운스 특성 비교
4. SysTick 타임스탬프 기반 소프트웨어 디바운싱을 구현하고 100회 반복으로 정량 검증

## 2. 구현

### 2.1 EXTI 신호 경로 — 세 개의 주변장치를 순서대로 연결

HAL이 한 줄로 감추는 EXTI 설정이 실제로는 서로 다른 세 주변장치의 협업이라는
것을 레지스터 레벨에서 직접 구현하며 확인했다.

```c
/* 1) SYSCFG: "어느 포트의" 13번 라인을 쓸지 라우팅 */
RCC->APB2ENR |= RCC_APB2ENR_SYSCFGEN;
(void)RCC->APB2ENR;
SYSCFG->EXTICR[3] &= ~(0xFU << 4);
SYSCFG->EXTICR[3] |=  (0x2U << 4);   /* 0010 = Port C → EXTI13 = PC13 */

/* 2) EXTI: 마스크 해제 + 트리거 엣지 선택 */
EXTI->IMR  |= (1U << 13);
EXTI->FTSR |= (1U << 13);            /* B1은 active-low → 하강 엣지 */

/* 3) NVIC: 벡터 활성화 */
NVIC_SetPriority(EXTI15_10_IRQn, 5);
NVIC_EnableIRQ(EXTI15_10_IRQn);
```

**설계 노트:** EXTI 라인 10~15는 개별 벡터가 아니라 `EXTI15_10_IRQHandler`
하나로 공유된다. 핸들러 진입 후 `EXTI->PR`의 어느 비트가 원인인지 확인하는
절차가 필수다.

### 2.2 핵심 함정 — PR 레지스터는 rc_w1

```c
void EXTI15_10_IRQHandler(void)
{
    if (EXTI->PR & (1U << 13)) {
        EXTI->PR = (1U << 13);      /* 1을 "써서" 클리어 (rc_w1) */
        edge_count++;
        ...
    }
}
```

Pending 레지스터는 **write-1-to-clear(rc_w1)** 타입이다. 직관적으로 보이는
`EXTI->PR &= ~(1U << 13)`(0을 쓰는 방식)으로는 플래그가 지워지지 않아,
핸들러를 빠져나가는 즉시 재진입하는 **무한 인터럽트**에 빠진다. 레지스터
접근 타입을 레퍼런스 매뉴얼에서 확인해야만 피할 수 있는 함정이다.

### 2.3 플로팅 입력 문제 — 실측으로 발견

초기 측정에서 버튼을 누르지 않았는데도 신호가 완만한 "산 모양"으로 불규칙하게
요동치는 현상이 관측되었다. 원인은 PC13을 입력 모드로만 두고 풀업/풀다운을
설정하지 않아 핀이 **플로팅 상태**였기 때문이다.

```c
GPIOC->PUPDR &= ~(3U << (13 * 2));
GPIOC->PUPDR |=  (1U << (13 * 2));   /* 내부 풀업 → 미누름 시 확실한 HIGH */
```

내부 풀업 활성화 후 HIGH(3.3V)가 안정적으로 유지되고 노이즈가 사라졌다.
**"입력 모드는 리셋 기본값이라 설정 불필요"라는 통념이 풀업/풀다운까지
보장하지는 않는다**는 것을 실측으로 확인한 사례다.

(1) 해당 개체의 접점 품질이 양호했거나, (2) 10kΩ 풀업과 기생 커패시턴스가
형성하는 완만한 RC 특성이 미세 바운스를 흡수했을 가능성이다. 명확한 분리를
위해서는 여러 스위치 개체에 대한 반복 측정이 필요하며, 이는 후속 과제로 남긴다.

## 5. 소프트웨어 디바운싱 — SysTick 타임스탬프 방식

SysTick으로 1ms 시스템 틱을 만들고, 마지막 인터럽트로부터 20ms 이내의
재트리거를 무시하는 방식이다. 디바운싱 미적용 카운트(`edge_count`)와 적용
카운트(`edge_count_debounced`)를 **동일 ISR에서 동시에 집계**하여, 한 번의
실험으로 두 조건을 공정하게 비교했다.

```c
void EXTI15_10_IRQHandler(void)
{
    static uint32_t last_tick = 0;
    if (EXTI->PR & (1U << 13)) {
        EXTI->PR = (1U << 13);
        edge_count++;                          /* 원시 카운트 */
        if ((systick_ms - last_tick) > DEBOUNCE_MS) {
            edge_count_debounced++;            /* 디바운싱 적용 카운트 */
        }
        last_tick = systick_ms;
    }
}
```

> 본 챕터는 CH01의 PLL 설정을 포함하지 않아 HSI 16MHz로 동작한다.
> 따라서 `SysTick_Config(16000000 / 1000)`으로 1ms 주기를 구성했다.
> 클럭 구성이 다른 프로젝트에 이식 시 이 값이 조용히 틀어지는 지점임을 명시한다.

## 6. 정량 검증 — 100회 반복

| 조건 | 100회 누름 → 검출값 |
|---|---|
| 디바운싱 없음 (`edge_count`) | **100** |
| 디바운싱 20ms 적용 (`edge_count_debounced`) | **100** |

![100회 반복 — 두 카운트 모두 100](docs/debounce_comparison.png)

두 값이 정확히 일치했다. 이는 §3의 스코프 실측(다중 바운스 부재)과 정합하는
결과로, 이 스위치 개체에서는 바운스가 인터럽트 레벨의 오검출을 유발하지
않았음을 보여준다.

**결론:** 이 결과는 "이 개체의 이번 실험에서 오검출이 없었다"는 사실이지,
"디바운싱을 생략해도 된다"는 근거가 아니다. 스위치 바운스는 개체 편차·접점
노후화·온습도에 따라 달라지는 확률적 현상이므로, 실제 제품 펌웨어에서
디바운싱은 측정 결과와 무관하게 기본 포함하는 것이 올바른 설계다. 본 실험의
가치는 "디바운싱이 필요한 이유"를 신뢰 구간의 관점에서 이해한 데 있다.

## 7. 한계

- 사용한 두 스위치 모두 바운스가 미미하여 디바운싱 효과의 극적인 대비는
  얻지 못했다. 노후화된 스위치를 이용한 대조 실험은 후속 과제로 남긴다.
- 엣지 발생 → ISR 진입까지의 인터럽트 지연 시간 측정은 본 챕터 범위에서 제외했다.

# CH05 — TIM1 상보 PWM과 데드타임 실측

> **한 줄 요약:** 고급 타이머 TIM1의 상보 PWM을 레지스터 레벨로 구현하고, 데드타임
> 생성기(DTG)가 삽입하는 지연을 오실로스코프로 실측했다. DTG=0x20 설정 시 **실측
> 데드타임 2.000µs가 계산값(32 × 62.5ns)과 소수점 자리까지 일치**했다. 이 과정에서
> **STM32F411의 타이머 AF 매핑이 타 F4 시리즈와 다르다**는 사실을 실측 실패 → 
> 데이터시트 검증으로 확정하며, 2차 자료가 아닌 1차 문서를 근거로 삼는 습관을 체득했다.

---

## 1. 목표

1. TIM1 상보 PWM(CHx/CHxN) 출력을 레지스터 레벨로 구현
2. 데드타임(DTG) 설정값에 따른 실제 삽입 지연을 오실로스코프로 실측
3. 데드타임 0일 때의 동시 전환(shoot-through 위험 조건)을 파형으로 시연

**동기:** 상보 PWM + 데드타임은 가전 인버터(세탁기 드럼 BLDC, 컴프레서, 팬)
전력단 제어의 핵심이다. 모터·게이트드라이버 없이 오실로스코프 2채널만으로
인버터 게이트 구동의 타이밍 원리를 정량 검증하는 챕터다.

## 2. 핵심 발견 — F411의 타이머 AF 매핑은 다른 F4와 다르다

이 챕터에서 가장 값진 결과물은 코드가 아니라, **여러 2차 자료(블로그·포럼)가
제시하는 "일반적인 F4" AF 번호가 F411에서 그대로 통하지 않는다**는 것을 세 번의
실측 실패로 발견하고, ST 공식 데이터시트(Table 8)로 최종 확정한 과정이다.

| 신호 | 핀 | 타 F4 통념 | **F411 실제 (데이터시트 확정)** |
|---|---|---|---|
| TIM1_CH1N | PA7 | AF1 | **AF2** |
| TIM1_CH2N | PB0 | AF2 | **AF1** |

증상은 항상 동일했다 — **메인 채널은 3.3V 정상 출력, 상보 채널만 약 1V의
왜곡된 저진폭 신호.** AF 번호가 틀리면 해당 핀이 타이머에 물리적으로 연결되지
않아 하이임피던스에 가까운 상태가 되고, 인접 핀의 스위칭 신호가 용량성
커플링으로 유입되어 낮은 진폭으로 관측된다. 에러도 경고도 없이 "조용히 다른
신호"가 나오기 때문에, **결과 파형의 물리적 타당성 검증 없이는 발견할 수 없는
유형의 버그**다.

> **실험 이력:** 최초 검증은 CH1/CH1N(PA8/PA7)으로 수행했고, AF 매핑 문제를
> 추적하는 과정에서 CH2/CH2N(PA9/PB0) 구성으로 전환하여 이후 실험을 진행했다.
> 본 README의 코드와 데드타임 측정은 모두 CH2/CH2N 기준이다.

## 3. 구현 (TIM1_CH2 = PA9/AF1, TIM1_CH2N = PB0/AF1)

### 3.1 상보 PWM 설정

```c
/* PA9 = TIM1_CH2 (AF1) */
GPIOA->AFR[1] |= (0x1U << ((9-8)*4));
/* PB0 = TIM1_CH2N (AF1) — F411 전용 매핑, 타 F4의 AF2와 다름 */
GPIOB->AFR[0] |= (0x1U << (0*4));

/* 10kHz PWM, 듀티 50% (HSI 16MHz 기준) */
TIM1->PSC  = 0;
TIM1->ARR  = 1600 - 1;     /* 16MHz / 1600 = 10kHz */
TIM1->CCR2 = 800;

/* CH2 PWM 모드1 + CCR preload */
TIM1->CCMR1 |= (6U << TIM_CCMR1_OC2M_Pos) | TIM_CCMR1_OC2PE;

/* 이전 설정 잔재 제거 후 필요한 비트만 설정 (방어적 초기화) */
TIM1->CCER = 0;
TIM1->CCER |= TIM_CCER_CC2E | TIM_CCER_CC2NE;
```

### 3.2 고급 타이머 전용 함정 — MOE

```c
TIM1->BDTR |= TIM_BDTR_MOE;   /* Main Output Enable */
```

일반 타이머(TIM2~5)에는 없는, 고급 타이머(TIM1/TIM8) 전용 마스터 출력
스위치다. CCER로 채널을 인에이블해도 **MOE=0이면 물리적 출력이 전혀 나오지
않는다.** 모터 구동에서 출력을 하드웨어 레벨로 일괄 차단하기 위한 안전
장치이며, 브레이크(BKIN) 발생 시 하드웨어가 이 비트를 자동으로 클리어한다.

### 3.3 데드타임 설정과 계산

```c
TIM1->BDTR &= ~TIM_BDTR_DTG;
TIM1->BDTR |= (0x20U << TIM_BDTR_DTG_Pos);
```

DTG[7:0]은 상위 비트 패턴에 따라 4개 구간으로 나뉘는 비선형 인코딩이다.
최상위 비트가 0인 구간(0~127)에서는 단순 선형으로:

```
DT = DTG × t_DTS = 32 × (1/16MHz) = 32 × 62.5ns = 2000ns
```

## 5. 측정 — 데드타임 (핵심)

| DTG | 계산값 | 실측값 | 파형 관찰 |
|---|---|---|---|
| 0x00 | 0ns | ≈0 | 두 신호가 간격 없이 동일 시점에 교차 |
| 0x20 | 2000ns | **2.000µs** | CH2 하강 → 2µs 간격 → CH2N 상승 |

![DTG=0 — 간격 없이 교차 (shoot-through 위험 조건)](docs/deadtime_zero.jpg)
![DTG=0x20 — 커서 실측 2.000µs, 계산값과 일치](docs/deadtime_cursor.jpg)

**DTG=0x20의 실측값 2.000µs는 계산값과 커서 분해능 한계 내에서 완전히
일치했다.** 데드타임 구간 동안 CH2와 CH2N이 모두 LOW를 유지하는 것도
확인했다 — 즉 상·하단 스위치가 모두 꺼진 안전 구간이 소프트웨어 개입 없이
타이머 하드웨어 레벨에서 자동 삽입된다.

## 6. 이 실험이 증명하는 것

DTG=0에서 두 신호가 간격 없이 교차한다는 것은, 실제 하프브리지였다면 상단
스위치의 턴오프가 완료되기 전에 하단 스위치의 턴온이 시작되는 순간이
존재함을 의미한다. 이 순간 전원-접지 간 관통 전류(shoot-through)가 흐르며
스위칭 소자를 파괴할 수 있다. 데드타임은 이 구간에 "둘 다 꺼짐"을 강제
삽입하는 하드웨어 기능이며, 본 실험은 **그 삽입량이 레지스터 설정값으로
정밀하게(오차 측정 한계 이내) 제어됨**을 정량 검증했다.

## 7. 한계 및 후속

- DTG의 선형 구간(`0xx`, 0~7.9µs)만 검증했다. 상위 비선형 구간(`10x`/`110`/`111`)
  검증은 후속 과제다.
- BDTR 브레이크 입력(BKIN)을 통한 하드웨어 즉시 차단 실험은 본 챕터에서
  제외했다. 별도 실험으로 남긴다.
- 무부하(프로브 커패시턴스만) 조건 측정이므로, 실제 게이트 드라이버 부하에서의
  파형 형상은 달라질 수 있다.
