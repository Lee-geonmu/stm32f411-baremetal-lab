# CH01 — RCC/PLL 100MHz 클럭 설정 및 오실로스코프 실측 검증

> **한 줄 요약:** HAL 없이 레지스터 조작만으로 SYSCLK 100MHz를 구성하고,
> MCO2 출력을 오실로스코프로 실측하여 **이론값 대비 오차 +1.85%** 로 검증했다.
> 이 과정에서 3건의 계측 오류를 순차적으로 진단·해결하며 측정 신뢰성을 확보했다.

---

## 1. 목표

- HSI 16MHz → PLL → **SYSCLK 100MHz** 구성 (STM32F411 최대 동작 주파수)
- 설정된 클럭이 "코드상으로만 100MHz"가 아니라 **물리적으로 실재하는지** MCO2(PC9) 핀 출력을 통해 계측기로 증명
- 클럭 설정 시퀀스의 순서 의존성(VOS → Flash latency → PLL → 버스 분주 → SW 전환)을 이해하고 구현

## 2. 구현

### 2.1 PLL 파라미터 설계

| 파라미터 | 값 | 근거 |
|---|---|---|
| PLLM | 8 | VCO 입력 = 16MHz / 8 = **2MHz** (RM0383 권장 1~2MHz 상한) |
| PLLN | 100 | VCO 출력 = 2MHz × 100 = **200MHz** (허용범위 100~432MHz) |
| PLLP | /2 | SYSCLK = 200MHz / 2 = **100MHz** |
| AHB | /1 | HCLK = 100MHz |
| APB1 | **/2** | F411 APB1 최대 50MHz 제약 준수 |
| APB2 | /1 | 100MHz |

### 2.2 순서가 강제되는 설정 시퀀스

```c
/* 1) PWR 클럭 인에이블 + VOS Scale 1 — 100MHz 동작의 전제조건 */
RCC->APB1ENR |= RCC_APB1ENR_PWREN;
(void)RCC->APB1ENR;                     /* 에라타 대응 더미 리드 */
PWR->CR |= PWR_CR_VOS;

/* 2) Flash 3WS — PLL 전환 "전에" 반드시. 순서 위반 시 하드폴트 */
FLASH->ACR = FLASH_ACR_LATENCY_3WS
           | FLASH_ACR_PRFTEN | FLASH_ACR_ICEN | FLASH_ACR_DCEN;
while ((FLASH->ACR & FLASH_ACR_LATENCY) != FLASH_ACR_LATENCY_3WS) { }

/* 3~7) HSI 확인 → PLL 설정/기동 → 버스 분주 → SW=PLL 전환 (main.c 참조) */
```

**설계 노트**
- `RCC->AHB1ENR` 인에이블 직후의 더미 리드는 STM32F4 에라타
  *"Delay after an RCC peripheral clock enabling"* 대응이다. AHB 버스 지연으로
  인에이블 직후 페리페럴 레지스터 쓰기가 무시될 수 있다.
  **HAL이 내부적으로 처리해주는 것을 레지스터 레벨에서는 직접 책임져야 하는 대표 사례.**
- `GPIOA->MODER`는 리셋값이 `0xA8000000`으로 PA13/PA14(SWD)가 AF 설정되어
  있으므로, 전체 쓰기가 아닌 read-modify-write로만 조작했다.
  (전체 쓰기 시 디버거 연결이 끊긴다.)

### 2.3 검증 경로 — MCO2

PC9를 AF0(MCO2)으로 설정, SYSCLK/5를 출력:
- 이론 출력 = 100MHz / 5 = **20MHz** (주기 50ns)
- 프리스케일러를 /5로 둔 이유: 100MHz 원신호는 프로브/스코프 대역폭 한계에서
  파형 무결성을 확보하기 어려우므로, 검증 가능한 주파수 대역으로 낮춰 출력

## 4. 계측 문제 해결 기록 — 3건

측정 초기에 **물리적으로 불가능한 값들**(74MHz, 34MHz, Pk-Pk 7.6V, 최저점 -2.24V)이
관측되었다. F411의 최대 클럭이 100MHz이므로 74MHz×5=370MHz는 존재할 수 없는
신호라는 판단에서 출발하여, 원인을 순차적으로 분리·제거했다.

| # | 증상 | 원인 | 해결 | 판별 근거 |
|---|---|---|---|---|
| 1 | 20MHz 사각파가 사인파처럼 뭉개짐 | 스코프 **대역제한 필터(20MHz)** 활성 상태 | 필터 OFF | 측정 대상 주파수와 필터 차단 주파수가 일치 → 고조파 소실 |
| 2 | 진폭이 측정마다 요동 (1V~7.6V) | 프로브 팁 ↔ 핀헤더 **접촉 불량** | M-F 점퍼로 기계적 고정 | DMM 평균전압은 안정(1.3V) ↔ 스코프 순간값만 요동 → 접촉 경로 문제로 특정 |
| 3 | 최저점 **-2.24V** 등 물리적 불가능 값 | **그라운드 리드 인덕턴스** (긴 악어클립) | 프로브 슬리브 제거 후 단축 점퍼로 그라운드 직결 | GPIO는 0~3.3V만 출력 가능 → 음전압은 계측 아티팩트로 확정. 조치 후 첨두치 3.64V로 안정화 |

**교훈:** 주파수/주기 측정은 제로크로싱 타이밍 기반이라 위 오류들의 영향을 적게 받아
일관된 값(20.3~20.4MHz)을 유지한 반면, 순간 전압 측정은 그라운드 경로와 접촉 품질에
직접적으로 좌우되었다. **계측기가 표시하는 숫자를 그대로 믿지 않고, 물리적 타당성으로
교차검증하는 습관**이 이 챕터의 실질적 산출물이다.

## 5. 한계

- 사용 장비(TDS224, 100MHz 대역폭·1GS/s)에서 20MHz 신호의 파형 미세 형상(모서리
  샤프니스)은 실시간 샘플링 한계로 완전한 재현이 어렵다. 본 챕터의 결론은 파형
  형상이 아닌 **주파수 정량 측정**에 근거한다.
- HSI 기반이므로 ±1~2% 수준의 주파수 오차는 원리적으로 제거 불가.
  정밀 클럭이 필요한 응용(USB 등)은 HSE가 전제되어야 함을 확인했다.

  # CH02 — GPIO 드라이버 설계, OSPEEDR 슬루레이트 실측, 함수 추상화 비용 정량화

> **한 줄 요약:** 레지스터 레벨 GPIO 드라이버를 직접 설계하고 두 가지 실험을 수행했다.
> ① OSPEEDR 4단계 실측 — **무부하 조건에서는 설정 간 차이가 발현되지 않음**을 확인하고
> 부하 의존성으로 원인을 규명했다. ② 함수 추상화 비용 벤치마크 — 별도 컴파일 단위의
> 함수는 -O2에서도 **4.8배** 느렸으나, `static inline` 전환으로 **레지스터 직접 접근과
> 완전히 동일한 성능(5 cycles/toggle)** 을 달성했다.

---

## 1. 목표

1. 재사용 가능한 GPIO 드라이버(`my_gpio.h/.c`)를 레지스터 레벨로 설계
2. OSPEEDR(슬루레이트) 4단계가 상승시간/오버슈트에 미치는 영향 실측
3. "함수로 감싸면 느려진다"는 통념을 **DWT 사이클 카운터로 정량화**하고,
   극복 방법(`static inline`)까지 실증

## 2. 실험 A — OSPEEDR 슬루레이트 실측

### 2.1 방법

- 대상: PC8 (외부 회로가 전혀 연결되지 않은 자유 핀 — LD2처럼 LED/저항이
  달린 핀은 파형 왜곡으로 배제)
- BSRR 토글 루프로 구형파 생성, OSPEEDR을 00→11로 변경하며 4회 반복 측정
- 상승시간: 사용 장비(TDS224)에 자동 Rise Time 측정 기능이 없어
  (TDS2MM 확장모듈 필요) **Voltage 커서로 10%/90% 레벨(0.36V/3.16V)을 산출한 뒤
  Time 커서로 ΔT를 수동 측정**하는 표준 절차를 수행

### 2.2 결과

| OSPEEDR | 첨두치 | 상승시간 (10–90%) |
|---|---|---|
| 00 (Low) | 3.52V | **82ns** |
| 01 (Medium) | 3.52V | ~80ns (오차범위 내 동일) |
| 10 (Fast) | 3.52V | 동일 |
| 11 (High) | 3.52V | 동일 |

### 2.3 분석 — 왜 차이가 없는가

4단계 모두 동일 값으로 수렴한 것은 오측정이 아니라 **부하 조건의 귀결**이다.

- 슬루레이트 제어의 본질은 출력 드라이버의 구동 능력(등가 임피던스 R) 조절이며,
  상승시간은 **τ ≈ R × C_load** 에 지배된다.
- 본 실험의 부하는 프로브 입력 커패시턴스(10x 프로브, 십수 pF)뿐으로,
  데이터시트 슬루레이트 스펙의 표준 시험 조건(≈50pF)보다 훨씬 가볍다.
- **C_load가 충분히 작으면 R의 차이가 τ에 유의미하게 반영되지 않는다** —
  4단계가 82ns 부근으로 수렴한 것은 이 조건에서 이론적으로 예측되는 결과다.

**실무적 시사점:** 슬루레이트 설정의 효과는 부하 의존적이다. 버튼·LED처럼
가벼운 부하의 GPIO에 High 설정을 쓰는 것은 속도 이득 없이 EMI 방사 리스크만
키우는 선택이며, **"요구 속도를 만족하는 최저 슬루레이트"가 올바른 기본값**이다.
가전제품은 EMI 인증이 출하의 실제 관문이므로 이 원칙의 무게가 크다.

## 3. 실험 B — 함수 추상화 비용 정량화

### 3.1 방법

- DWT 사이클 카운터(`CYCCNT`)로 10,000회 토글 소요 사이클 측정

- 컴파일러의 루프 제거를 막기 위해 결과 변수를 `volatile`로 선언

### 3.3 분석

- **-O2에서도 4.8배 차이가 남는 이유:** GCC는 링크 타임 최적화(LTO) 없이는
  **다른 컴파일 단위(translation unit)의 함수를 인라인하지 않는다.**
  `my_gpio.c`에 구현된 함수는 호출(call/return) 오버헤드가 그대로 잔존했다.
- **`static inline` 전환 효과:** 함수 본문을 헤더로 이동해 호출부와 같은
  컴파일 단위에 두자, -O2에서 **레지스터 직접 접근과 1 cycle 이내로 동일**해졌다.
- 이는 CMSIS를 포함한 임베디드 라이브러리들이 저수준 접근자를 헤더에
  inline으로 구현하는 설계 관행의 근거를 직접 재현한 것이다.

**결론:** "추상화 = 성능 손실"은 조건부 명제다. 컴파일 단위 배치를 이해하고
`static inline`을 적용하면, **가독성·재사용성·타입 안전성을 가진 드라이버
계층을 제로 코스트로 구축할 수 있다.**

## 4. 산출물

- `my_gpio.h` — `static inline` 접근자 + 초기화 API (재사용 가능, 이후 챕터의 기반)
- `dwt.h` — 사이클 정밀 벤치마크 유틸리티 (10ns 분해능 @100MHz)

## 5. 한계 및 후속 계획

- 슬루레이트 실험은 무부하 단일 조건이므로, 표준 부하(수십 pF) 조건에서의
  단계별 차이 분화는 검증하지 못했다. 부하 커패시터를 추가한 조건별 재실험은
  후속 과제로 남긴다.
- HAL(`HAL_GPIO_TogglePin`) 동일 조건 비교는 HAL 미포함 프로젝트 구성상
  제외했다. 별도 브랜치에서의 비교를 후속 과제로 남긴다.

# CH04 — EXTI 인터럽트, 버튼 바운스 실측, 소프트웨어 디바운싱

> **한 줄 요약:** 레지스터 레벨로 EXTI 외부 인터럽트를 구현하고, 온보드 버튼(B1)과
> 외부 택트스위치의 기계적 바운스를 오실로스코프로 실측했다. 두 스위치 모두 예상보다
> 미미한 바운스를 보였으며, 100회 반복 실험으로 디바운싱 유무에 따른 오검출 차이를
> 정량 검증했다. "측정해보니 문제없었으나, 그것이 디바운싱 생략의 근거는 아니다"라는
> 안전 마진 관점의 결론을 도출했다.

---

## 1. 목표

1. EXTI 외부 인터럽트를 레지스터 레벨로 구현 (SYSCFG → EXTI → NVIC 경로)
2. 버튼의 기계적 채터링(bounce)을 오실로스코프 싱글샷으로 직접 캡처
3. 온보드 B1(PC13)과 외부 택트스위치(PB0)의 바운스 특성 비교
4. SysTick 타임스탬프 기반 소프트웨어 디바운싱을 구현하고 100회 반복으로 정량 검증

## 2. 구현

### 2.1 EXTI 신호 경로 — 레지스터 레벨의 3단계

HAL이 한 줄로 감춰주는 EXTI 설정을, 실제로는 세 개의 서로 다른 주변장치를
순서대로 연결해야 한다는 것을 직접 구현하며 확인했다.

```c
/* 1) SYSCFG로 "어느 포트의" 13번 핀을 EXTI13에 연결할지 지정 */
RCC->APB2ENR |= RCC_APB2ENR_SYSCFGEN;
(void)RCC->APB2ENR;
SYSCFG->EXTICR[3] &= ~(0xFU << 4);
SYSCFG->EXTICR[3] |=  (0x2U << 4);   /* 0010 = Port C → EXTI13 = PC13 */

/* 2) EXTI 주변장치에서 마스크 해제 + 트리거 엣지 선택 */
EXTI->IMR  |= (1U << 13);            /* 인터럽트 마스크 해제 */
EXTI->FTSR |= (1U << 13);           /* B1은 active-low → 하강 엣지 */

/* 3) NVIC에서 해당 벡터 활성화 */
NVIC_SetPriority(EXTI15_10_IRQn, 5);
NVIC_EnableIRQ(EXTI15_10_IRQn);
```

**설계 노트 — PC13은 EXTI13이고, EXTI13은 EXTI15_10 벡터로 묶인다.**
EXTI 라인 10~15는 개별 벡터가 아니라 하나의 공유 인터럽트 핸들러
(`EXTI15_10_IRQHandler`)로 처리된다. 따라서 핸들러 안에서 `EXTI->PR`의
해당 비트를 확인해 어느 라인이 발생시켰는지 구분해야 한다.

### 2.2 핵심 함정 — PR 레지스터는 rc_w1이다

```c
void EXTI15_10_IRQHandler(void)
{
    if (EXTI->PR & (1U << 13)) {
        EXTI->PR = (1U << 13);      /* 1을 "써서" 클리어 (rc_w1) */
        edge_count++;
        ...
    }
}
```

Pending 레지스터(PR)는 **`rc_w1`(read-clear, write-1-to-clear)** 방식이다.
플래그를 지우려면 해당 비트에 **1을 써야** 한다. 직관적으로 보이는
`EXTI->PR &= ~(1U << 13)`처럼 0을 쓰면 클리어되지 않아, 핸들러를 빠져나가는
즉시 다시 진입하는 **무한 인터럽트**에 빠진다. 레지스터 접근 타입(rc_w1)을
데이터시트에서 확인하지 않으면 놓치기 쉬운 함정이다.

### 2.3 플로팅 입력 문제 — 내부 풀업 필수

초기 측정 시 버튼을 누르지 않았는데도 신호가 완만한 "산 모양"으로
불규칙하게 흔들리는 현상이 나타났다. 원인은 PC13을 입력 모드로만 두고
풀업/풀다운을 설정하지 않아 **핀이 플로팅 상태**였기 때문이다. 플로팅 핀은
주변 노이즈를 그대로 주워 전압이 정해지지 않는다.

```c
GPIOC->PUPDR &= ~(3U << (13 * 2));
GPIOC->PUPDR |=  (1U << (13 * 2));   /* 내부 풀업 → 안 눌렀을 때 확실히 HIGH */
```

내부 풀업을 활성화하자 안정된 HIGH(3.3V)가 유지되고 노이즈가 사라졌다.

## 5. 소프트웨어 디바운싱 — SysTick 타임스탬프 방식

SysTick으로 1ms 시스템 틱을 생성하고, 인터럽트 발생 시각을 비교해
일정 시간(20ms) 이내의 재트리거를 무시하는 방식으로 구현했다.

```c
void EXTI15_10_IRQHandler(void)
{
    static uint32_t last_tick = 0;
    if (EXTI->PR & (1U << 13)) {
        EXTI->PR = (1U << 13);
        edge_count++;                          /* 디바운싱 없는 원시 카운트 */
        if ((systick_ms - last_tick) > DEBOUNCE_MS) {
            edge_count_debounced++;            /* 디바운싱 적용 카운트 */
        }
        last_tick = systick_ms;
    }
}
```

> SysTick은 리셋 후 기본 클럭인 HSI 16MHz 기준으로 `SysTick_Config(16000000/1000)`
> 하여 1ms 주기를 만들었다. (본 챕터는 CH01의 PLL 100MHz 설정을 포함하지 않는다.)

# CH05 — TIM1 상보 PWM과 데드타임 실측

> **한 줄 요약:** 고급 타이머 TIM1의 상보 PWM(CHx/CHxN)을 레지스터 레벨로 구현하고,
> 데드타임 생성기(DTG)가 만드는 지연을 오실로스코프로 실측했다. DTG=0x20 설정 시
> **실측 데드타임 2.000µs가 계산값(32 × 62.5ns = 2000ns)과 소수점까지 정확히 일치**했다.
> 이 과정에서 STM32F411의 타이머 AF 매핑이 다른 F4 시리즈와 다르다는 사실을 실측으로
> 발견하고 데이터시트로 검증했다.

---

## 1. 목표

1. TIM1 상보 PWM 출력을 레지스터 레벨로 구현
2. 데드타임(DTG) 값에 따른 실제 지연을 오실로스코프로 실측
3. 데드타임 0일 때 발생하는 상하단 동시 도통(shoot-through) 위험을 파형으로 시연

**동기:** 상보 PWM + 데드타임은 가전 인버터(세탁기 BLDC 드럼 모터, 컴프레서, 팬)의
전력단 제어 핵심이다. 모터 없이 오실로스코프 2채널만으로 인버터 게이트 구동의
기초 원리를 검증하는 챕터다.

## 2. 핵심 발견 — F411의 타이머 AF 매핑은 다른 F4와 다르다

이 챕터에서 가장 값진 경험은, 여러 참고 자료(블로그·포럼)가 제시하는
"일반적인 F4 시리즈" AF 번호가 **F411에서는 그대로 맞지 않는다**는 것을
실측 실패를 통해 발견하고, ST 공식 데이터시트로 최종 확정한 과정이다.

| 신호 | 핀 | 흔한 통념(타 F4) | **F411 실제(데이터시트 확인)** |
|---|---|---|---|
| TIM1_CH1N | PA7 | AF1 | **AF2** |
| TIM1_CH2N | PB0 | AF2 | **AF1** |

증상은 항상 동일했다 — **메인 채널(CHx)은 3.3V 정상 출력, 상보 채널(CHxN)만
약 1V의 왜곡된 신호.** AF 번호가 틀리면 그 핀이 타이머에 연결되지 않아
플로팅에 가까운 상태가 되고, 인접 핀의 신호가 커플링되어 낮은 진폭으로
나타난다. 데이터시트 Table 8의 나열 순서(AF1부터)를 직접 확인해 각 핀의
정확한 AF를 확정한 뒤에야 두 채널 모두 정상 출력되었다.

**교훈:** 같은 STM32F4 제품군이라도 핀-주변장치 매핑은 파트 넘버마다 다르다.
2차 자료가 아닌 해당 파트의 데이터시트를 1차 근거로 삼아야 한다.

## 3. 구현

### 3.1 상보 PWM 설정 (TIM1_CH2 = PA9, TIM1_CH2N = PB0)

```c
/* PA9 = TIM1_CH2 (AF1) */
GPIOA->AFR[1] |= (0x1U << ((9-8)*4));
/* PB0 = TIM1_CH2N (AF1) — F411 전용 매핑 */
GPIOB->AFR[0] |= (0x1U << (0*4));

/* 10kHz PWM, 50% 듀티 (HSI 16MHz 기준) */
TIM1->PSC = 0;
TIM1->ARR = 1600 - 1;      /* 16MHz / 1600 = 10kHz */
TIM1->CCR2 = 800;          /* 50% */

/* CH2 PWM 모드1 + preload */
TIM1->CCMR1 |= (6U << TIM_CCMR1_OC2M_Pos) | TIM_CCMR1_OC2PE;

/* 레지스터를 0으로 초기화 후 필요한 비트만 설정 (이전 설정 잔재 제거) */
TIM1->CCER = 0;
TIM1->CCER |= TIM_CCER_CC2E | TIM_CCER_CC2NE;   /* CH2, CH2N 출력 인에이블 */
```

### 3.2 두 가지 필수 함정

**(1) MOE — 고급 타이머만의 마스터 출력 인에이블**

```c
TIM1->BDTR |= TIM_BDTR_MOE;   /* 이거 없으면 CHx/CHxN 출력 자체가 안 나온다 */
```

일반 타이머(TIM2~5)에는 없고 고급 타이머(TIM1, TIM8)에만 있는 비트다.
CCER로 채널을 인에이블해도 MOE가 0이면 물리적 출력이 전혀 나오지 않는다.

**(2) 레지스터 초기화 순서**

CCER과 BDTR을 `|=`로만 설정하지 않고 `= 0`으로 먼저 밀었다. 동일 타이머를
이전에 다른 설정으로 쓴 흔적(극성 비트 등)이 남아 상보 채널이 오동작하는
것을 방지하기 위한 방어적 초기화다.

### 3.3 데드타임 설정

```c
TIM1->BDTR &= ~TIM_BDTR_DTG;
TIM1->BDTR |= (0x20U << TIM_BDTR_DTG_Pos);   /* DTG=32 */
```

DTG[7:0]은 상위 비트 패턴에 따라 계산식이 4구간으로 나뉜다. 최상위 비트가
0인 `0xx` 구간(0~127)에서는 단순히 **DT = DTG × t_DTS**이다.
t_DTS = 1/16MHz = 62.5ns이므로:

```
DTG = 0x20 = 32  →  32 × 62.5ns = 2000ns = 2µs
```

**DTG=0x20 실측값 2.000µs는 계산값 2000ns와 소수점 자리까지 정확히 일치했다.**
데드타임 구간에서는 CH2와 CH2N이 모두 LOW를 유지한다 — 즉 상단·하단 스위치를
모두 끄는 안전 구간이 하드웨어 타이머 레벨에서 자동 삽입됨을 확인했다.

## 6. 이 실험이 증명하는 것

DTG=0에서 두 신호가 간격 없이 교차한다는 것은, 실제 인버터 하프브리지였다면
**상단 스위치가 완전히 꺼지기 전에 하단 스위치가 켜지는 순간**이 존재함을
의미한다. 이 순간 두 스위치를 통해 전원-그라운드 간 단락 전류(shoot-through)가
흐르며, 이는 게이트 소자를 즉시 파괴할 수 있다. 데드타임은 이 위험 구간을
제거하기 위해 두 스위치가 모두 꺼진 시간을 강제로 삽입하는 기능이며, 본
실험은 그 삽입량이 DTG 설정값대로 정확히 제어됨을 정량적으로 검증했다.

## 7. 한계 및 후속

- 데드타임을 `0xx` 구간(0~7.9µs)에서만 실험했다. 상위 구간(`10x`, `110`, `111`)의
  비선형 인코딩 검증은 후속 과제로 남긴다.
- BDTR의 브레이크 입력(BKIN)을 통한 하드웨어 즉시 차단은 본 챕터에 포함하지
  않았다. 별도 실험으로 남긴다.
- 실측은 무부하(프로브 입력 커패시턴스만) 조건이다. 실제 게이트 드라이버
  부하에서의 파형은 다를 수 있다.
